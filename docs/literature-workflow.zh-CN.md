# Literature：从兴趣到可追溯的文献认识

Literature 帮助用户理解一个领域、找到相关工作、阅读关键材料并形成下一步问题。Research Chat 的首轮应交付有内容的领域导览；正式科研阶段继续通过现有 landscape、targeted_source 和 novelty_check 合同取得有明确适用边界的外部依据。

## 分层执行

1. **检索规划**：独立作业先用当前 Literature 模型生成少量互补学术查询及领域锚点，覆盖机制、代表体系、近期工作或相反条件。正式 Cycle 的 Lead 文献请求在原提案交付中提供 `search_queries` 和 `relevance_terms`，SDK 校验并原样传递，不另加规划模型调用。查询使用适合来源索引的主题词，包括英文索引所需的英文查询；旧请求未提供这些字段时仍保留原兼容路径。规划记录单独持久化，不充当文献证据。避免将整段自然语言问题直接传入检索 API。旧作业恢复继续采用其原执行版本。
2. **来源发现**：SDK 执行公共学术 API、合并兼容 DOI/arXiv 身份、保留各查询和 provider 原始结果。异常题录在进入排序与 Agent 语料前隔离；排序以科学相关性为主。短名单有界，完整原始结果留作追溯。
3. **重要来源选读**：Literature 依据科学问题和互补性挑选材料，SDK 获取对应原文。来源锁定、合法开放获取、实际文章内容、文献身份及转换设置分别核验。摘要、正文可用、正文覆盖范围和 Agent 已核对是不同状态。预印本补齐 DOI 时保留同一论文的阅读身份；摘要版本按来源保留，精确引句可绑定其实际出现的版本。
4. **证据综合**：保留原有来源引用、精确引句和访问层级核验；解释机制、适用条件、近邻工作、分歧与可研究的问题。领域尚未解决的问题进入 open_questions；具体缺失来源检查才进入剩余调研需求。报告展示精选论文，完整题录留在索引中。
5. **缺口补查与恢复**：在既定轮数/来源预算内，只对具体缺口规划补充查询。默认最多两轮、六次来源获取。已完成的检索、规划和阅读持久化复用，取消和访问失败保留真实状态。
6. **聊天交付**：首次独立会话中明确的搜文献请求由 host 等待 Literature，进度直接投影到页面，完成后将有界报告交给 Chat 解读。父聊天模型无需持续轮询。复杂上下文和后续问题继续保留既有 CLI 委派能力。详情展示阶段梳理、选读论文和可核验引用，原始命中折叠并标为待筛选；原始命中数量不代表已阅读或相关论文数量。

材料获取与已启用的 PDF 转换使用一致的时间预算；超时或取消清理整个子进程组。读取筹备页面不等待整轮材料事务，修改计划和创建项目仍遵守排他锁与版本复核。报告中的内部来源编号转换为论文标题链接。

SDK 引句定位检查与科学解释分别记录。恢复已保存的交付时，可用原始 Agent JSON 和已保存材料重算访问回执；不改原始响应、科学主张或引句，不以该重算冒充新模型阅读。

## 材料、请求与恢复校验

同标题或相同索引键不构成论文身份相同的证明。候选合并核对 DOI、arXiv 及适用的作者、年份；有冲突或多义时保留独立记录。用户指定的来源锁与检索命中分别保存，只有身份核对成功后才绑定，不能靠检索服务返回的自声明取得锁定状态。

检索缓存绑定完整的规范化请求与材料哈希。同一缺口增加新线索或改换来源时使用新的资料目录，保留旧证据；恢复仅复用请求一致且材料未变的记录。连接器失败保持明确失败原因，不因已有缓存目录就视为成功检索。

正式 Cycle 的文献 Evidence 必须绑定唯一来源、实际保存的 SDK 材料与可定位引句。摘要不能冒充正文，阅读清单中的 `read` 标记不能替代正文文件。登记后再次核对输入哈希；材料缺失或变化时保留原记录，停止将其作为可裁决证据。这些检查证明材料与引句的对应关系，科学解释仍由科研 Agent 和 Judge 判断。

独立作业保存原始响应后，语法或合同错误通过原响应离线复验；恢复不覆盖原响应或无限追加模型调用。传输重试有次数限制并保留原线程，未取得持久响应的悬空调用须先恢复身份。SDK 自行创建的模型后端在退出时清理，调用方传入的后端由调用方管理。

新完成作业为交付及依赖材料保存完整性清单，再次运行和页面状态读取会检查清单。交付或材料损坏时显示未完成或失败，不自动重做科研。历史无清单作业只能复核现存材料并明确其历史边界，不能补造原始哈希证明。

## 与现成方案的关系

设计参考已有研究系统的分层方法：STORM/Co-STORM 的多视角问题规划、dzhng/deep-research 的互补查询与有界递进，以及 PaperQA2 的来源材料和证据综合分离。检索由随包提供的 `tm-scholar` 执行，使用现有 Codex 账号模型路由与 Sciver 的科学合同，共享同一套科学状态和项目生命周期。

参考：[STORM](https://github.com/stanford-oval/storm)、[dzhng/deep-research](https://github.com/dzhng/deep-research)、[PaperQA2](https://github.com/Future-House/paper-qa)、[Deep Agents](https://github.com/langchain-ai/deepagents)。前三者分别提供领域探索、轻量迭代检索和论文证据问答的设计参考；具体许可证与依赖以各上游为准。

## 保留的接口和权威

共享 scholarly transport 仍支持 landscape、targeted_source、novelty_check，保留 source_lock、引用追踪、合法 OA 阅读、可选 Marker/MinerU、原始来源和错误回执。正式 Cycle 的 Stage/Contract、Lead/Judge 权威不变。独立 Chat 作业不创建 H、科学 Evidence、Scientific Model 或 Task，不因完成调研而自动立项或启动研究。

## 验收

确定性回归覆盖查询规划、异常题录、跨查询合并、来源身份、访问层级、引句绑定、引用追踪、转换开关、恢复与取消，以及 Chat 的 host 等待和报告注入。

真实用户流程固定首句：`我对于高分子的拓扑和力学感兴趣,搜搜文献看看.`。使用全新 Research Chat 筹备会话与当前模型配置。审核完整查询、材料、Agent 输出、报告与主答复，判断用户是否获得有用导览、可核验相关论文、受来源支撑的机制与阅读方向。记录等待时间、调用和缓存/非缓存用量，由独立 Agent 审核实际浏览器体验；不以 API 返回成功或候选篇数代替质量。

实际结果、用量和剩余限制见 [真实流程验收](literature-acceptance-20261118.zh-CN.md)。该记录区分真实模型交付、确定性回归与已保存材料的离线重验。
