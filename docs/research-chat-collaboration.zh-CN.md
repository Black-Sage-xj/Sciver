# 与 Sciver 一起讨论和调整研究

Research Chat 是工作区的交互 Agent。它可以解释项目、核对证据、比较下一步，也可以在你同意具体方案或明确要求执行后调整研究。聊天会话与科研 Cycle 分开，讨论中的想法会保留其真实身份。

## 从阅读开始讨论

在图谱中打开一个节点、某轮结论或研究报告，使用“围绕此处讨论”。报告或文档中可以先选择一段文字。来源加入聊天草稿后，会显示对象、章节、选段和来源版本；你可以移除它，继续编辑问题，再发送。选择来源不会自动发送或启动研究。

发送时 Sciver 会重新核对来源。来源已经变化时，重新打开原文并添加；旧消息保留发送时的来源快照，便于回看当时讨论的依据。讨论所选对象时，Sciver 可以继续读取有关报告与证据。

## 日常聊天操作

项目显示在输入框上方。左下角“＋”添加材料，右下角的模型与推理强度入口集中调整本轮设置；展开输入框和发送快捷键位于“更多输入选项”。对话查找、版本与文件位于消息区上方；查找与文件互斥展开为浮层，点击外部或按 Escape 收起。回复完成通知位于“更多输入选项”。历史记录在左侧，可收起；窄屏使用历史抽屉。未指定项目时，新对话直接从独立探索开始；也可主动选择已有项目。文献调研卡片可随时打开完整问题、候选文献和 Agent 阅读进展。研究计划草稿可从工具区重开，计划具备目标、约束和完成标准后，审阅立项入口出现在对话末尾。

“科研工具”提供三个起点：**了解研究进展**看当前状态、成果和卡点；**讨论问题与想法**用于解释现象、核查结论和推敲新想法；**规划下一步**用于比较方案、安排验证顺序，以及讨论计划或方向调整。选择入口只会准备可编辑的草稿，发送后才开始对话。

每条消息显示发送时间；回复显示生成用时、模型及可用的用量信息。生成中可展开公开的进度、工具操作和计划，刷新后仍能回看。这里的用时包含本轮等待、工具调用和输出时间。

输入框支持选择、粘贴和拖入图片，也支持 PDF、DOCX、Markdown、TXT、CSV。每条消息最多 10 个附件，每个不超过 20 MB；可以只发送图片。上传失败可以重试，未发送的附件随草稿保留。PDF 使用可提取的文字并标记页码；扫描件需要先转成文字或发送页面图片。此处的基础附件读取与 Settings 中可选的论文 PDF 转换分别配置。

回复期间可以补充指令或把后续问题加入队列；带附件或来源的问题进入队列。队列中的问题可以编辑、移除。停止回复会暂停队列，点击继续才会发送剩余问题。Sciver 提供选项问题时，可直接选择或填写回答。

编辑重发、重新生成会保留旧版本，可以切换查看；也可以从指定消息建立分支对话。消息和选中文字支持引用。聊天支持搜索并跳到原文、项目筛选、置顶、归档、移入回收站与恢复，以及导出 Markdown 或 JSON。

本聊天文件集中显示上传材料与回复中的成果文件，支持预览、下载。代码支持高亮、复制和下载，表格支持复制及 CSV 导出，图片支持放大，长回复可折叠并按标题导航。输入框可展开，并可选择 Enter 或 Ctrl/Cmd+Enter 发送；完成通知按需开启。

## 从讨论到行动

当讨论形成可执行的下一步时，Sciver 在回复末尾用 1、2、3 列明实际需要的改动，并说明原因、涉及的路径、当前工作和生效时点，再询问是否执行。你可以接受、修改方案，或指定只执行某些项。

常见调整有五类：

| 调整 | 用途 |
| --- | --- |
| Research Plan | 更正目标、约束、完成标准或长期背景；列明具体章节和内容 |
| 下一轮猜想 | 指定精确命题和判别检验，交给新一轮提案与资格审查 |
| Scientific Model | 基于具体来源修正当前认识，说明错误、遗漏、适用范围与仍未知的部分 |
| 研究路径 | 暂缓或关闭指定路径；保留已有记录和裁决 |
| 运行 | 暂停、启动或恢复指定工作；说明资源与执行范围 |

只有新想法时，不必改写长期目标或当前稳定认识。Scientific Model 的更正单独说明依据；用户偏好和待检验猜想不会自动成为已证实结果。

你明确说“按第 1、3 项修改”，Sciver 就执行这两项；仅接受计划修改不包含启动科研。方案已明确包含运行、且你接受整个方案时，无需再次确认同一范围。

## 下一轮与立即转向

新猜想默认供下一次全新提案使用一次。当前已经冻结的命题继续按原检验执行。新提案仍由 Research Lead 与 Challenger 审查，通过后才成为正式 H，并进入 Investigator 工作。

恢复已冻结的 Cycle 会继续它原来的命题。登记一个新猜想，不等于已经开始研究该猜想。等待中的猜想可以明确撤销或替换；已交给某个 Cycle 的命题保留该轮记录。

若需要立即改变当前工作，请在方案中说明暂停和转向的范围。Sciver 使用安全控制并核实当前工作已停止，再提交即时转向请求；它会保留原 Cycle 及证据，并分别报告哪些已经完成、哪些仍待执行。

## 看执行回执

Sciver 按你接受的编号逐项回复：

- 已修改的内容、版本与来源；
- 已登记但等待下一次提案的猜想；
- 实际已冻结的 H、已启动的 Cycle 或 Worker；
- 尚未生效、失败或部分完成的操作及原因。

运行成功与科学结论分别记录。任务是否完成，以正式 Goal 判定为准。

## 正式立项之前

打开 Research Chat 的新对话页，在“创建新项目”中选择“已有明确问题”或“从兴趣或现象开始”。无需已有任务，也不需要先写完整合同；先从问题、兴趣或观察开始讨论。

筹备对话使用独立空间保存研究意图、文献材料和计划草稿。两种起点都需核对相关工作；问题需要文献时，Chat 可在你的请求范围内主动调用现有 Literature Agent，复用其身份、技能和输出合同。Literature 梳理领域、选择重要论文、阅读比较并按缺口补查；Chat 与你讨论这些结果。该过程会调用模型，使用已配置的模型账号额度。

复现、数值试算、原型实验、参数扫描和补算都要先有审阅过的研究计划并正式立项，再通过该 Task 的 SDK Cycle 执行。即使只是“小尺寸先跑一次”，也按这个顺序。立项前可以继续讨论、核对文献、查看已有图片和数据，或重绘已有数据帮助理解。

准备立项时，点击“审阅计划并创建项目”。可以修改项目名称、研究意图和四段 Research Plan，也可以先保存空草稿、返回讨论。创建要求 `Goal / Research Contract / Final Gate / Required Context` 各段已有实质内容；Scientific Model 由 SDK 空白初始化。草稿变化会提示重新审阅，保留当前输入。

“确认创建项目”会生成独立 Task、空白科研图谱和空白 Scientific Model，并冻结筹备对话与资料快照。重复提交返回同一项目。创建后，原对话使用正式项目的最新上下文继续协作；点击“打开正式项目”进入任务页也可查看运行。明确要求启动时，Chat 通过正式项目的运行接口执行并核验 Cycle/Worker；只问如何开始时提供操作说明。筹备记录继续保留为来源。流程与 Literature 作业说明见[项目筹备与前置文献调研](../design/项目筹备与前置文献调研.md)。

遇到立项或服务错误时，科研对话会核对失败记录并保留输入。需要修改应用源码、运行软件测试或部署修复时，使用独立的[系统助手](/research-chat/?channel=system)。


## 文献调研和 PDF 转换

Literature 作业默认最多 2 轮、6 个核心来源获取尝试。达到资源上限仍有问题时，保留已完成材料并暂停，报告哪些主张缺少原文支持。使用同一作业恢复会复用已有检索和已完成阅读；“作业完成”表示交付了此次范围内的调研，不代表问题已解决或研究已获科学裁决。

新安装默认关闭 PDF 转换。打开 **Settings（`/settings`）→ PDF 转换**，可按服务主机的能力选择：

1. **本地 Marker**：配置可执行文件路径，或让 `marker_single` 位于服务进程的 `PATH`。Sciver 不假定每台主机都已安装，也不会自动安装转换器。你本机启用后仅影响这台服务的配置。
2. **在线 MinerU**：配置 API Token，或由管理员设置服务环境变量 `MINERU_API_KEY`。执行转换会上传 PDF；Token 私有保存在服务器，设置页仅显示是否已配置。留空保存会保留原 Token，选择清除才删除。

关闭转换后仍可检索论文、阅读摘要与可访问的 HTML 正文。已下载 PDF、已转换文本、Literature 阅读和原文主张核验是不同层级。默认转换前 20 页，可在设置中调整，填 0 表示所有可处理页；前 N 页不能称为整篇已核验。调研材料保留原 PDF、转换记录、图片及版面文件，便于追溯关键公式、图表和引文。
