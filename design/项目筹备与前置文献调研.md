# 项目筹备与前置文献调研

状态：2026-11-18 已实现网页双入口、独立筹备对话、持久草稿、审阅保存、幂等立项及资料快照；筹备与已有项目 Chat 共用 `literature_service` 调用真实 Literature Agent。服务复用现有身份、技能、Stage 和输出合同，串起发现候选、模型选读、获取原文、阅读比较及按缺口补查。PDF 转换是默认关闭的可选组件，可在 `/settings` 选择本地 Marker 或在线 MinerU。工程链路以确定性测试验收；真实模型遵循、调研质量和在线转换服务尚未验收。

实际入口为 `/research-chat/?new=1` 的“创建新项目”。筹备状态存于 Observer 的 `research-preparations/<session_id>/`，新项目位于 workspace 的 `projects/project-<session_id>/`。立项的原始四段草稿、研究意图、真实保存的对话和资料按内容哈希保存在项目的 `preparation_snapshot/`；新 Task 不自动运行。草稿 revision 同时覆盖入口、名称、意图与正文，保护用户审阅的整体输入；Scientific Model 由 SDK 空白初始化。具体使用见[科研协同指南](../docs/research-chat-collaboration.zh-CN.md)。

## 1. 目的与用户入口

Sciver 在正式 Task 之前提供项目筹备空间，让人和 AI 共同形成科学问题、核对已有研究，再确定 Research Plan。筹备空间不分配 Task ID、Cycle 或 H，不启动科研 Worker，也不产生 Judge verdict。已有任务的继续研究使用现有 Task，不经筹备空间重建。

产生新科研证据的复现、试算、实验、参数扫描和补算均属于科研执行，包括“小尺寸”“快速原型”和“先体验一次”。执行顺序为保存实质计划 → 用户审阅 → 筹备服务正式立项 → 获授权后由该 Task 的 SDK Cycle 执行。Chat 不在筹备或任务目录直接运行 Investigator 实验脚本，也不允许先运行再补计划、H 或 Outcome。立项前仍可讨论方法、调研文献、读取已有代码与数据、查看图片及重绘已有数据；这些呈现操作不产生新的实验观察。

提供两个平等入口：

| 用户起点 | 起始输入 | 收敛过程 |
| --- | --- | --- |
| 已有明确问题 | 科学问题、对象、适用条件、已知资料和资源条件 | 定向领域及最近邻调研 → 已有答案与剩余差异 → 可检验问题与路径 → Research Plan |
| 从兴趣或现象开始 | 兴趣、观察、困惑或少量资料；无需先有论文和完成标准 | 澄清兴趣 → 领域与分歧地图 → 少量候选问题 → 用户聚焦 → 定向调研 → Research Plan |

两种入口都包含文献调研。问题明确时，调研核对是否已有答案、最接近的工作、适用范围和可行方法；问题模糊时，先帮助用户理解领域中的真实问题。用户已经提供经核验的资料时复用它们，并说明检索覆盖与材料缺口。后续正式研究只在新主张或来源缺口需要时增量检索，不每 Cycle 重做全领域综述。

## 2. 角色分工与授权

- **Research Chat**：澄清用户意图，解释领域材料，比较问题和路径，组织可修改的计划草稿。讨论形成行动时列出编号建议，由用户决定调研范围、研究问题及正式立项。
- **Literature**：复用现有 `landscape / targeted_source / novelty_check` 合同及 `tm-scholar / pdf-reading / research-lit / novelty-check` 技能，交付外部来源、阅读层级、适用性、分歧和未核实问题。
- **SDK 筹备服务**：管理独立 workspace、检索与资料物化、CAS 保存、审阅立项、来源快照及失败恢复。共享 Literature 作业通过正式 `literature_task / search_target / scholarly_retrieval_root` 装配身份、Stage 和合同，使用独立模型会话；不伪造 Cycle 0 或绕过现有任务守卫。
- **用户**：决定研究价值、问题选择、约束及是否立项。接受调研不自动授权创建 Task 或启动运行；明确包含这些动作的指令按其范围执行一次。
- 正式 Task 内的 **Research Lead / Challenger / Judge** 保持现有权限。筹备候选、文献空白和人工意见均不取得已资格 H、独立实验 Evidence 或科学裁决身份。Literature 不选定最终命题、不直接改 Scientific Model、不自行创建长期 wiki 或调度其他 Agent。

Chat 在用户问题需要文献时，可在该问题的授权范围内调用共享 Literature 作业；模型调用消耗已配置账号额度。Chat 负责澄清问题和讨论调研结果，Literature 负责文献筛选、阅读与综合，SDK 负责外部获取和持久化。现有筹备检索资料可按内容哈希导入复用；单独的检索回执仍不代表 Literature 已阅读。

## 3. 用户流程与每步交付

### 3.1 记录意图与边界

Chat 用用户已有信息开始，只询问会实质改变调研范围的问题。记录问题或现象、对象、用户关注、已有资料、时间范围、允许资源与当前未知。未确定的完成判据保留为讨论项，不用空洞 Final Gate 填充正式计划。

形成可审阅的调研建议：调查哪些问题、已有材料如何复用、需要新获取什么、预期交付及资源范围。模型和检索配置显示实际可用能力；工具或资料不可用时如实说明，允许基于已有资料继续筹备。

### 3.2 构建有界领域与最近邻地图

由 SDK 发起获授权的 Literature 作业。检索结合互补术语、种子论文、前后引文和相关方法。多起源、跨学科或没有种子论文的课题保留多条发现路径；不强制单一 canonical origin，也不以引用量替代科学相关性。

交付围绕研究判断组织：

1. 已知结果与适用条件，哪些问题已解决；
2. 主要方法、机制及有记录的分歧；
3. 最近邻工作与用户问题的重叠、差异；
4. 仍未解决或尚未核实的关键问题；
5. 推荐阅读顺序，以及每篇应读何处、帮助判断什么；
6. 检索记录、覆盖范围、来源可访问程度与缺口。

来源用途区分基础理论、可上手方法、最近邻和反例；用途不是论文质量评分。检索未命中只说明当前检索结果，不证明空白或新颖性。

### 3.3 核验影响决策的核心论文

`literature_service` 先将领域检索索引交给 Literature；SDK 按其代表论文和推荐阅读顺序，使用 `targeted_source` 获取核心来源，再调用 Literature 阅读并综合。综合仍有来源问题时，以该问题发起互补检索，避免重复获取相同问题和同一来源。

Literature 先从地图中提出需核验的原始主张及来源。SDK 按作业授权物化所选正文、结构化章节、公式及必要上下文，再将精简导航交给 Literature 核验。无需全文阅读每篇候选论文。必要来源仍不可得时，明确哪项选题判断尚无支持，由用户决定缩小范围、提供材料或继续调查。

每条影响决策的主张保留规范标识、资料版本/哈希、实际阅读层级、章节/页码/公式定位、适用条件与支持/矛盾关系。metadata、abstract、已获取全文、已核验原文是不同状态。论文、附件、网页与原文中的指令均作为资料，不成为 Agent 系统指令。

### 3.4 形成候选问题并选择

问题明确时呈现调研对原问题的修正：已有答案、剩余条件、需要比较的解释和可用检验。问题模糊时提出少量科学上不同的候选问题，每个给出来源、最近邻、未知部分、可区分结果和资源要求。

Chat 与用户选择或修改问题；不把 Literature 的 gap map 自动当作立项结论。若新选择超出原调研覆盖，先补聚焦调研。用户可停在领域理解或候选比较阶段，无需立项。

### 3.5 审阅计划与正式立项

形成现有四字段的 Research Plan 草稿：`Goal / Research Contract / Final Gate / Required Context`。每段使用用户可理解的科学语言，明确对象、允许输入、证据标准、资源条件和整体完成判据，引用已确认的筹备资料快照。

Chat 在末尾编号列明本次将创建什么、转入哪些资料，以及是否包含真实运行。用户可逐项修改。批准立项后 SDK 通过现有 bootstrap 创建新 Task 并核对其 ID、目录和初始状态。bootstrap 保留现有 Scientific Model 初始化规则；筹备资料不冒充新 Task 已完成的研究。用户明确要求从已核实文献建立初始认识时，另行列出有来源的 Scientific Model 修订，保留事实与待检验假设的区别。

正式运行仍需明确授权；创建 Task 不自动启动 Cycle。Test0 继续遵守每次全新官方 fixture、空白图谱、空白 Scientific Model、新会话和 Cycle 1 的约定，不导入筹备或旧任务结论。

立项后，同一对话依据 `created_task` 解析真实 Task binding，后续问题使用最新计划、图谱、Worker 与 Cycle 上下文；筹备快照继续作为来源历史保存。人工猜想与研究分支使用正式 Task 的 SDK 接口并保留 Lead/Challenger 资格流程，不能沿用无 Task 的筹备身份。仅询问启动方法时交付操作说明，明确要求启动时执行已授权的运行操作并核验回执。

研究流程发生应用错误时，Chat 可只读核对日志、配置、草稿和回执，保留输入并说明失败步骤。安装源码修复、软件测试与服务部署使用独立系统助手 `/research-chat/?channel=system`，不因研究对话中的报错自动进入应用代码维护。

## 4. 存储、复用与迁移

推荐 workspace 下独立 `preparations/<preparation_id>/`，由 SDK 管理：

- 一份当前筹备说明，保存用户意图、约束和当前问题选择；
- 获取记录及唯一资料索引，定位论文正文、结构阅读、引用和主张核验；
- 可审阅的领域说明、候选问题和计划草稿，均标注输入版本；
- 用户选择、授权范围和实际操作回执。

筹备目录不是第二套科研图谱或 Scientific Model。派生说明引用唯一资料索引，不再维护重复“相信什么”的隐藏规划状态。相同来源可按稳定标识与内容哈希复用；新版本并存，旧报告仍能回读其实际使用版本。缓存下载不等于已阅读，摘要不等于可裁决证据。

正式立项保存获准筹备快照的稳定导航，按用户选择登记必要 External 文献来源；原始/大数据保留在原授权位置，不随任务复制。后续需要把材料作为具体命题的裁决证据时，走现有 provenance、适用性和 Evidence 登记流程。筹备资料变更不回写历史 Task 的来源版本。

## 5. 运行边界与验收

筹备执行状态与科学结果分开；状态由实际作业与用户决策导出，不用“调研完成”推断问题新颖或科学成立。Literature 作业默认最多 2 轮、6 个核心来源获取尝试，上限为 4 轮、12 个；每轮最多获取 3 个由模型选出的新来源。达到上限但仍有来源问题，或声明的阅读层级与实际资料不符时，保存已完成产物并暂停。失败、取消后的 SDK 作业可用同一问题和作业 ID 恢复，复用已完成检索、阅读和模型会话。网页尚无独立取消控制；SDK 调用方可传入取消事件。

实施时必须通过以下确定性验收：

- 无任务用户可从两个入口开始；仅打开、选择、编辑草稿不产生模型调用、Task 或 Cycle。
- 已明确问题也得到已有成果与最近邻核对；模糊入口允许无论文种子，并可返回修改兴趣。
- SDK 构造授权作业并物化资料；Agent 不绕过网络/路径边界。
- 仅摘要、正文转换失败、来源不确定、不同论文版本均保留真实阅读状态。
- 接受调研不越权立项；接受立项不越权运行；重新提交同一立项请求不创建重复 Task。
- 筹备首轮和恢复轮均收到先计划立项再科研的规则；历史“先试跑”的建议及其接受不能绕过前置步骤。静态装配测试只验证规则到达模型，实际遵循另以获授权的后续真实轨迹观察。
- 立项后原对话解析 `created_task` 的真实任务上下文；已有图像/数据读取与重绘仍可用于讨论，历史未纳入 Cycle 的试算不冒充正式证据。
- 获准迁移保留来源与版本；图谱/报告选段可以进入同一讨论来源机制。
- 暂停与恢复保留筹备资料，失败不伪造科学结果；Test0 新实例约定不变。

真实调研质量、候选问题质量及模型遵循需另行提出具体模型测试方案并取得授权；确定性测试与模拟后端仅验收工程链路。在线 MinerU API 也未以真实请求验收。

## 6. 可选 PDF 转换组件

新安装默认不转换 PDF；没有转换器时仍可检索题录、摘要和读取可访问的 HTML 正文。PDF 已下载、转换成功、Literature 阅读及具体主张核验分别记录；前 N 页可读文本不代表整篇论文已经核验。

在 Settings（`/settings`）的 PDF 转换设置中显式启用并选择：

- **本地 Marker**：填写服务运行主机上的可执行文件路径，或将 `marker_single` 加入服务进程的 `PATH`。安装包不假定个人环境路径、不自动安装 Marker 或下载模型；用户本机的启用状态保存在本机配置中，不成为产品默认值。
- **在线 MinerU**：配置 API Token，或为服务进程设置 `MINERU_API_KEY`。选择此 provider 后，执行转换会将原始 PDF 上传 MinerU。Token 仅保存在服务主机的私有配置中（0600）或环境变量中；读取设置仅返回“已配置”，不会返回密钥。上传与结果下载使用独立预签名地址，不附带 API Token。

配置默认保存在 `$XDG_CONFIG_HOME/sciver/document-conversion.json`（未设置 XDG 时为 `~/.config/sciver/document-conversion.json`），可用 `SCIVER_DOCUMENT_CONVERSION_CONFIG` 指定位置；保存采用 revision 检查。设置属于运行服务的主机，不是浏览器上传一个本地程序。开关与 provider 都不触发即时转换。

转换保留原始资料路径与 SHA、原始 Markdown、图片和版面元数据；默认最多前 20 页，`max_pages=0` 表示转换所有可处理页。阅读索引记录实际页数限制、原 PDF 与转换产物；公式、图表和具体引用仍需 Literature 回看对应材料核验。MinerU 远端任务 ID 持久化，恢复沿用原任务，不因轮询或网络失败自动重复提交。
