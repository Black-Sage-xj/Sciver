# Numerical Investigation

## 输入与执行

- 先查再算，复用优先。围绕冻结的 decisive test 核对必要输入、来源、适用范围与参数。在已授权材料和任务历史中寻找可用记录。区分数据本身、已有结果和本次重新分析；若任务要求复算或复现，执行相应步骤。
- 决定性字段缺失时，先查权威 source 或 builder 是否可用现有授权输入重建，复用此前已核实的缺口，仅重查发生变化的部分。不能恢复时记录具体 external_artifact 缺口。可行的推导或替代实现须保持同一科学检验。对同一材料的多个已知检查可合并为一个 batch probe。
- 昂贵方法先用数量级或小试验估计判别力与时间、内存、存储。最坏情况上界只约束相应方法。成本失衡时停止该方法，尝试冻结范围内的可行替代；预算及中断由 SDK 管理，不得自行将未执行的检验判为不可判明。
- 扩大批量计算前，若独立计算单元达到 10 个或预计串行超过 10 分钟，加载 compute-dispatch。规模变化时重新评估并行、内存及磁盘；优先复用已有产物。正式作图加载 plotting，领域方法只用当前任务授权的 Skill。
- 使用 runtime 的科学 Python。在计算目录以 README 记录输入与关键参数、运行入口、产物和复现方式。local_source_review 只读取获准的任务本地材料。

## 检验与证据

按原题与冻结检验所需的证据强度选择验证方式。普通 train/validation 比较按指定划分和顺序执行，报告分组、方法选择及可能影响推断的数据使用。没有额外的 SDK 盲测认证要求。只有明确要求受保护评价或主张的成立依赖事前隔离时，才须按真实独立单位保留并核查相应材料；已暴露的结果或事后生成的数据不能追认为原先未触碰的盲测。路径、哈希或 Agent 自述本身不能证明事前冻结。来源未认证只限制相应身份主张。

根据结论选择适当的正确性检查，例如原题给出的 reference、解析特例或可信实现。重复运行和输出一致只能证明可重复或自洽。若结论取决于误差估计，也核对能改变判断的不确定性计算；不要求统一校正公式、样本阈值或额外大规模模拟。用实际方法和限制表述检查结果，无需另建验证报告。区分冻结判据、拟合前明确的方法选择与事后变更，后选的判断规则也不能追称为预设条件。
