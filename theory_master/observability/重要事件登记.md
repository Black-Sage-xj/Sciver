# TheoryMaster 重要事件登记（包含原异常）

2026-10-09 起**新记录**统一写入 `important_events.jsonl`，仍按 Cycle 目录保存；重大跨 Cycle 控制事件也在 Task 的 `research_root/important_events.jsonl` 去重登记。已存在的 `cycle_anomalies.jsonl` 保留原样，读取时兼容汇合；不得批量覆盖历史原始日志。

- `severity=error`：系统失败；`attention`：需要处理/额度暂停；`minor` 等：合同重试、JSON 规范化等异常；`important`：非故障的重要科学/运行控制事件。

## 2026-10-18 展示职责分流

持久化文件名 `important_events.jsonl` 是兼容用历史名称，不等于所有内容都应展示在 Web「重要事件」。Web 从同一原始 JSONL 生成三种独立读模型：`severity=important` 的重要里程碑、其它严重程度的按案例合并异常记录、按**当前停机状态**生成的待处理通知。三者不互相触发。`registered/recurred/resume_attempt` 都保留在异常案例详情中；同一 `incident_id` 的重复登记不是多次重要事件，也不是多次通知。通知回执不会把恢复尝试变为成功。
- `kind=preferred_focus_started`：已经在 Canvas 观察到 `active + priority: preferred` 且有 External ResearchFocus 记录。
- `kind=preferred_focus_exhausted`：该已启动 ResearchFocus 起点的全部可达科学后继 tip 均为 closed。**只在事件首次出现时登记科研优先级提示**；不停止下个 Cycle、不阻断下一次 `tm run`、不发送邮件，不自动标记 Goal PASSED，也不删除旧 H。历史上同名事件保留原记录，但不再具备运行控制权。
- 原注册、锁、事件去重和通知重试 API 保持兼容。新 Schema `theory-master/important-event/v1`；旧 `theory-master/cycle-anomaly/v2` 仍可读取。
- 本类 preferred 提示不触发邮件；真正无法继续运行的故障或额度事件由各自通知策略处理。历史通知回执保持原样，不伪造新的 sent。配置应由环境变量/专用 secrets 管理，不应将凭据写入 Canvas。
- 故障和高级事件之间不得混淆：preferred 线路结束仅是优先研究提示，不能伪造 `run.failed`、Judge rejected、Task complete，亦不能挟持科研生命周期。
